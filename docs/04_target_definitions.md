# Retention Intelligence Platform

## Target Definitions & Modeling Specification

**Document status:** Foundational
**Version:** 1.0

---

# 1. Purpose

This document defines the targets that the analytical system will predict.

The project contains multiple targets because customer retention is not adequately represented by one binary churn label.

---

# 2. Target Hierarchy

The modeling system consists of:

```text
TARGET 1
Churn propensity

TARGET 2
Time-to-churn

TARGET 3
Customer Lifetime Value

TARGET 4
Treatment uplift

TARGET 5
Decision outcome
```

These targets have different meanings and must not be conflated.

---

# 3. Target 1 — 30-Day Churn

Definition:

```text
Y30 = 1
if customer churns during [T0, T0 + 30 days]

Y30 = 0
otherwise
```

Purpose:

> Identify immediate retention risk.

---

# 4. Target 2 — 90-Day Churn

Definition:

```text
Y90 = 1
if customer churns during [T0, T0 + 90 days]

Y90 = 0
otherwise
```

Purpose:

> Identify medium-term retention risk.

---

# 5. Target 3 — 180-Day Churn

Definition:

```text
Y180 = 1
if customer churns during [T0, T0 + 180 days]

Y180 = 0
otherwise
```

Purpose:

> Support longer-term customer planning.

---

# 6. Why Multiple Horizons

A single churn probability hides timing.

Compare:

```text
Customer A
P(churn 30d)  = 0.80

Customer B
P(churn 30d)  = 0.30
P(churn 180d) = 0.82
```

A and B require different strategies.

A requires urgent intervention.

B may require behavioral monitoring and early engagement rather than an immediate discount.

---

# 7. Target 4 — Survival

The survival target represents:

```text
T = time until churn
```

with:

```text
event = 1
```

if churn is observed.

If churn is not observed before the observation period ends:

```text
event = 0
```

and the observation is treated as right-censored.

---

# 8. Target 5 — Customer Lifetime Value

CLV is defined as:

> Expected future economic value generated by the customer from the prediction timestamp onward.

The implementation will distinguish:

```text
Revenue CLV
```

from:

```text
Contribution / Profit CLV
```

where sufficient information exists.

The project will not assume revenue equals profit.

---

# 9. CLV at Risk

Define:

```text
CLV at Risk
=
Expected CLV
×
Probability of Churn
```

This is an initial prioritization approximation.

The production implementation may use a more rigorous survival-based expected-loss calculation.

---

# 10. Target 6 — Treatment Uplift

For an intervention `T`:

```text
Uplift(X)
=
E[Y(1) - Y(0) | X]
```

where:

```text
Y(1) = outcome under treatment

Y(0) = outcome under control
```

The objective is to estimate:

> The expected incremental effect of treatment for a customer with characteristics X.

---

# 11. Treatment Outcome

The exact treatment outcome depends on the causal dataset.

For the Criteo uplift dataset, the project will use its available randomized treatment/control and response variables rather than inventing a telecom-specific treatment effect.

The methodology will then be translated into the retention decision framework.

---

# 12. Treatment Effect Interpretation

Example:

```text
Predicted retention without treatment:
40%

Predicted retention with treatment:
65%

Estimated uplift:
+25 percentage points
```

This does NOT mean:

> The customer has a 65% probability of retention in every real business.

It means:

> Under the modeled treatment-response assumptions, treatment is estimated to increase the outcome probability by approximately 25 percentage points.

---

# 13. Decision Target

The final decision system does not directly predict:

```text
"contact customer"
```

Instead it estimates:

```text
risk
+
timing
+
value
+
treatment response
+
cost
```

and derives an action.

---

# 14. Decision Value

Initial conceptual formulation:

```text
Expected Incremental Value

=
Expected Incremental Retained Value
-
Intervention Cost
```

The intervention is economically attractive when:

```text
Expected Incremental Value > 0
```

subject to business constraints.

---

# 15. Model Evaluation Targets

## Churn

Evaluate:

```text
PR-AUC
ROC-AUC
Brier Score
Calibration
Recall at operational capacity
Precision at operational capacity
```

---

## Survival

Evaluate using appropriate survival metrics such as:

```text
Concordance index
Integrated Brier Score
Time-dependent discrimination
Calibration
```

---

## CLV

Evaluate:

```text
MAE
RMSE
MAPE/sMAPE where appropriate
calibration by value segment
```

The evaluation must distinguish revenue prediction from profit prediction.

---

## Uplift

Evaluate:

```text
Qini
AUUC
uplift by treatment-score decile
policy value
incremental gain
```

---

# 16. Threshold Selection

Thresholds must not be selected arbitrarily.

Example:

```text
P(churn) > 0.50
```

is not automatically a useful business threshold.

Instead thresholds should be determined from:

```text
intervention capacity
cost
expected value
false-positive cost
false-negative cost
campaign constraints
```

---

# 17. Calibration Requirement

If the model outputs:

```text
0.80
```

the probability should have meaningful probabilistic interpretation.

Calibration will therefore be evaluated independently from ranking performance.

A model with excellent ranking but poor calibration may be unsuitable for economic decision-making.

---

# 18. Target Leakage Rules

The following cannot be used as predictors when they occur after T0:

```text
churn status
cancellation date
post-churn activity
post-treatment outcome
future revenue
future support interactions
future intervention response
```

---

# 19. Target Governance

Every target must document:

```text
definition
observation window
prediction horizon
source
event definition
censoring
missing-value behavior
evaluation metric
business interpretation
limitations
```

No model enters production without a documented target definition.
